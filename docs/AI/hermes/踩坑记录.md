# Hermes 安装、更新与配置踩坑记录

> 适用环境：macOS（darwin-x64）、通过官方安装脚本安装的 git 模式 Hermes。本文不记录 API Key、微信 Token、用户 ID 或密码；这些内容只能保存在
`~/.hermes/.env`，且不要提交到 Git。

- 安装目录：`~/.hermes/hermes-agent`
- 受管 Python：`3.14.7`

```bash
hermes gateway status
hermes config check
```

## 首次安装

官方安装命令：

```bash
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
```

安装中断后，不要急于删除 `~/.hermes`。安装脚本可以复用已下载的工具和源码；先按报错类型修复，再重试。若基础工具已成功安装，而安装器又因
GitHub 网络问题停在更新阶段，可在源码目录直接补全依赖：

```bash
hermes pm install
```

该命令会继续安装 Python 环境、浏览器工具等；`agent-browser` 下载包约 171 MB，网络较慢时需要等待，不应中途终止。

## 坑 1：旧淘宝 npm 源使用 HTTP

### 现象

安装器报错：

```text
npm: install failed: refusing non-https url:
http://registry.npm.taobao.org/npm/-/npm-12.0.2.tgz
```

### 原因

旧的 `registry.npm.taobao.org` 配置为 HTTP，Hermes 安装器拒绝通过非 HTTPS 地址下载 npm。

### 修复

检查：

```bash
npm config get registry
cat ~/.npmrc
```

将 `~/.npmrc` 调整为 HTTPS 的新镜像：

```ini
registry=https://registry.npmmirror.com
strict-ssl=true
```

或者使用官方 npm 源：

```ini
registry=https://registry.npmjs.org/
strict-ssl=true
```

验证：

```bash
npm config get registry
```

不要保留 `strict-ssl=false`，除非在明确知道企业 TLS 代理要求的情况下临时使用。

## 坑 2：HTTP 阿里云 PyPI 镜像导致 `cryptography` / `cffi` 解析失败

### 现象

安装 Python 依赖时出现类似错误：

```text
Failed to download and build `cryptography==50.0.1`
No solution found when resolving: ... `cffi>=2.0.0`
`cffi` was filtered by `exclude-newer`
```

继续临时豁免 `cffi` 后，又会出现：

```text
`pycparser` was filtered by `exclude-newer`
```

### 根因

用户 pip 配置中的旧 HTTP 阿里云源：

```ini
[global]
index-url = http://mirrors.aliyun.com/pypi/simple/
```

该镜像对部分包返回的上传时间元数据不完整。Hermes/uv 启用了 `exclude-newer` 供应链保护策略，因此会把这些包误判并排除，最终造成
`cryptography -> cffi -> pycparser` 依赖链无法解析。

### 正确修复

不要修改 `~/.hermes/hermes-agent/pyproject.toml` 或 `uv.lock` 去逐个豁免依赖；后续 `hermes update` 会覆盖这种临时修改，而且会掩盖镜像问题。

改为使用可访问、元数据完整的 HTTPS PyPI 源。编辑 `~/.pip/pip.conf`：

```ini
[global]
index-url = https://pypi.org/simple/
```

验证后重建环境：

```bash
pip config debug
hermes pm install
hermes pm doctor
```

如果网络环境无法直连官方 PyPI，应选择经过验证、支持 HTTPS 且能返回完整 PyPI 元数据的镜像；不要直接假定任一国内镜像都兼容 uv
的上传时间筛选。

## 坑 3：GitHub 网络不稳定导致安装器在更新阶段失败

### 现象

```text
git fetch failed
Failed to connect to github.com port 443
Failure when receiving data from the peer
```

### 处理原则

这是到 GitHub 的网络或代理问题，与 npm/Python 依赖问题无关。安装器必须先拉取 `NousResearch/hermes-agent`，因此无法访问
GitHub 时不会进入依赖安装步骤。

处理顺序：

1. 确认网络、VPN 或本地代理能够访问 `https://github.com`。
2. 若有本地 HTTP 代理，例如 Clash 的 `7890` 端口，可临时配置 Git：

```bash
git config --global http.proxy http://127.0.0.1:7890
git config --global https.proxy http://127.0.0.1:7890
```

3. 重试安装或更新：

```bash
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
# 或已安装后：
hermes update
```

4. 不再需要 Git 代理时取消配置：

```bash
git config --global --unset http.proxy
git config --global --unset https.proxy
```

不要把不受信任的 GitHub 代理永久写入全局 Git 配置。

## 坑 4：更新完成后命令警告 Gateway 仍是旧模块

### 现象

执行 `hermes sessions list` 等命令时出现：

```text
A previous `hermes update` pulled new code but did not restart running gateways.
Gateways may still be serving pre-update modules (mixed sys.modules).
```

这不是 `sessions list` 失败。若后面已输出会话表格，说明会话命令本身已成功执行。

### 修复

更新源码后重启 Gateway：

```bash
hermes gateway restart
sleep 8
hermes gateway status
```

正常结果应包含：

```text
Service definition matches the current Hermes install
Gateway is supervised by launchd
```

Gateway 重启会短暂中断微信等消息通道，并会等待正在处理的任务排空；避开长任务执行时段操作。

## 坑 5：OpenAI 兼容接口返回 `/chat/completions` 404

### 现象

日志中有：

```text
openai.NotFoundError: Error code: 404 - {"detail":"Not Found"}
base_url=http://<host>:8000
url=http://<host>:8000/chat/completions
```

### 根因

目标网关实现的是 OpenAI 风格的 `/v1/...` 路由，但配置的 `base_url` 少了 `/v1`。OpenAI SDK 因此请求了不存在的：

```text
http://<host>:8000/chat/completions
```

而正确路径是：

```text
http://<host>:8000/v1/chat/completions
```

### 修复

在 `~/.hermes/.env` 中将对应 provider 的地址改为带 `/v1` 的形式。以 Kilo Code 为例：

```ini
KILOCODE_BASE_URL=http://<host>:8000/v1
```

不要在文档、终端历史或截图中写入 API Key。修改后重启 Gateway：

```bash
hermes gateway restart
```

无认证探测时，以下现象说明路由已正确到达服务，不代表认证已成功：

```bash
curl -i http://<host>:8000/v1/models
# 常见结果：401，表示路径存在但需要认证

curl -i http://<host>:8000/v1/chat/completions
# 常见结果：405，表示路径存在但该接口需要 POST
```

### 仍可能出现：模型 ID 或订阅权限错误

路径修复后，若返回：

```text
HTTP 400: Invalid model ID or insufficient subscription level to use it
```

说明请求已经到达接口，问题变为模型名称不在该账号可用目录中，或订阅无权限；这与 `/v1` 路径无关。使用 `hermes model --refresh`
或该网关的已认证 `/v1/models` 目录选择实际可用模型，再进行最小测试：

```bash
hermes --provider kilocode --model <可用模型ID> --oneshot "Reply with exactly: OK"
```

切换默认模型前，先保留可工作的 provider，避免让微信 Gateway 没有可用模型。

## 微信接入的安全选择

配置向导中建议：

| 问题                                          | 推荐选择                      | 原因                               |
|---------------------------------------------|---------------------------|----------------------------------|
| `How should direct messages be authorized?` | `Use DM pairing approval` | 新联系人必须经过配对授权，避免陌生人调用本地工具或消耗模型额度。 |
| `How should group chats be handled?`        | `Disable group chats`     | 默认不在任何微信群响应，降低误触发与费用风险。          |

需要开放指定群时，使用 `Only allow listed group chat IDs`，不要使用 `Allow all group chats`。

## 更新和重装标准流程

### 日常更新

```bash
hermes update
hermes pm install
hermes gateway restart
hermes --version
hermes pm doctor
hermes gateway status
```

只有在 `hermes pm doctor` 显示核心工具正常、`hermes gateway status` 显示服务定义匹配且 Gateway 被 `launchd` 托管时，才认为更新完成。

### 重新安装前检查

```bash
cat ~/.npmrc
cat ~/.pip/pip.conf
curl -I https://github.com
```

应至少满足：

```ini
# ~/.npmrc
registry=https://registry.npmmirror.com
strict-ssl=true

# ~/.pip/pip.conf
[global]
index-url = https://pypi.org/simple/
```

然后执行：

```bash
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
hermes pm doctor
```

## 故障快速索引

| 现象                                       | 优先检查                      | 修复方向                                             |
|------------------------------------------|---------------------------|--------------------------------------------------|
| `refusing non-https url`                 | `npm config get registry` | 将 npm 源改为 HTTPS。                                 |
| `cffi`、`pycparser` 被 `exclude-newer` 过滤  | `pip config debug`        | 替换为元数据完整的 HTTPS PyPI 源，然后运行 `hermes pm install`。 |
| `git fetch failed`                       | GitHub 连通性、代理             | 修复网络/代理后重试，不要删除已有安装。                             |
| 运行后出现 Gateway 旧模块警告                      | `hermes gateway status`   | `hermes gateway restart`。                        |
| OpenAI SDK 请求 `/chat/completions` 返回 404 | provider `BASE_URL`       | OpenAI 兼容网关通常需要以 `/v1` 结尾。                       |
| `/v1` 已正常但模型返回 400                       | 模型目录、账号订阅                 | 选择该 key 实际可用的模型 ID。                              |
| `pm doctor` 有多个 `? not installed`        | 是否需要对应功能                  | 仅按需安装可选工具。                                       |

## 安全注意事项

- `~/.hermes/.env` 包含模型 API Key、微信凭据及其他敏感信息，权限建议收紧：`chmod 600 ~/.hermes/.env`。
- 不要把 `~/.hermes/.env`、请求转储文件、日志文件提交到 Git 或发到公开渠道。
- 终端输出、报错截图可能携带 `base_url`、会话内容、请求体甚至凭据；对外分享前先脱敏。
- 不要将 `SUDO_PASSWORD` 等高权限凭据长期明文保存在项目仓库或同步笔记中。
